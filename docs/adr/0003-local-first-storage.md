# Local-first storage; no cloud sync in v1; sync-ready schema; on-device embeddings

All Memory data lives on-device only (Room + FTS5 + sqlite-vec). There is no cloud sync in v1 and no hosted backend: embeddings are computed on-device so Memory text never egresses for retrieval, and the schema is designed sync-ready from day one (row UUIDs, tombstones, mutation timestamps) so E2EE sync or backup can land later without a data migration. This follows from the privacy posture (ADR-0002) and the no-backend economics: a memory app silently mirroring personal data to its vendor cloud (the reference OEM app synchronizes everything to its proprietary cloud) would betray the product premise. Consequences: data loss on an unbacked device is the real risk, mitigated later by E2EE backup; cloud embeddings and cloud sync are rejected as defaults.
